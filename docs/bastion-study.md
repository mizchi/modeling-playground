# BASTION-06 — 地上重装型モジュール機

添付された重装二脚メカの画像を参考にした、RAVENとは別のオリジナル機体。アーマード・コア系の「小さなセンサー頭部・重い接地脚・露出フレーム・左右非対称の武装」を造形の軸にする。特定の公式機体の精密複製ではない。

[ローカルで開く](http://127.0.0.1:5188/?model=bastion) / [標準構成GLB](../output/bastion.glb) / [パーツ規格JSON](../output/bastion.parts.json)

## 今回の造形

- 低背の光学センサー頭部、傾斜した胸部装甲、狭い旋回腰、幅広い脛装甲と長い足底。全身を同じ太さにせず、装甲と関節の細さを対比させた。
- 胸前面だけを押し出さず、背面のリアクター・双発パック・冷却部、ふくらはぎ側の動力部まで作る。側面からも胴体と脚が薄い板にならないことを先に検査。
- 膝を少し前、足首を後ろ、爪先を長くした接地姿勢。接続ピン、油圧シリンダー、配管を装甲の隙間へ配置した。
- オリーブドラブ／暗い内部フレーム／露出金属のPBR材質。小さな識別ステンシルと塗装の粒子・微小な欠けは決定的なDataTextureで生成し、GLBへ内包する。大きな汚しや手描きの全面UVアトラスではない。
- 左手の回転機関砲と右手の長砲身ライフル、左肩の6連装ミサイルと右肩の榴弾砲を標準構成にした。左右は機体自身から見た向き。

標準構成は約6.36 m高（肩砲含む）、15,210三角形、296メッシュ、約1.01 MiB。今回はPS1向けのポリゴン上限を設定していない。分離メッシュ数は交換・フォーカスの扱いやすさを優先したもので、ゲーム向け描画呼出し最適化は未実施。

## 11か所の交換規格

| 接続口 | 選択肢 | 交換単位 |
| --- | --- | --- |
| `head` | 低背センサー／指揮通信型 | 頭とアンテナ |
| `core` | 重装傾斜装甲／哨戒装甲 | 胴・旋回腰・骨盤 |
| `leftArm`, `rightArm` | 重装マニピュレータ／作業用フレーム | 肩装甲から手まで、左右独立 |
| `leftLeg`, `rightLeg` | 重装接地脚／野戦脚 | 股関節から足底まで、左右独立 |
| `backpack` | 双発動力パック／冷却パック | 背部装備 |
| `leftWeapon`, `rightWeapon` | ライフル／回転機関砲／なし | 左右の手持ち武装 |
| `leftShoulder`, `rightShoulder` | ミサイル／榴弾砲／なし | 左右の肩武装 |

`models/bastion-definition.mjs`を原本に、選択肢・標準構成・接続位置を固定。規格名は`bastion-v1`、メートル、Y-up、+Z前方、+Xが機体の左。規格と状態はThree.jsやDOMから独立したデータであり、形状実装は再生成できる。

```text
BASTION-06  extras: modelId, assemblyVersion, loadout
├─ Mount_core          共通接続位置
│  └─ core_fortress    交換対象（形状・材質を所有）
├─ Mount_head
│  └─ head_sensor
├─ Mount_leftArm / Mount_rightArm
├─ Mount_leftLeg / Mount_rightLeg
├─ Mount_backpack
├─ Mount_leftWeapon / Mount_rightWeapon
└─ Mount_leftShoulder / Mount_rightShoulder
```

各部品は自分の接続口のローカル座標で生成する。交換は接続口の子だけを差し替え、他のモジュールと接続行列を維持する。未知の接続口・非互換の部品IDは変更前に拒否する。各モジュールが材質・テクスチャを所有し、交換時の解放が他パーツに波及しないようにする。

今の接続口は静止アセンブリ用の共通シャシー座標。動くスケルトンに追従するソケットではない。関節可動を追加するときは手・肩装備の接続口をボーンに追従させ、脚の接地、油圧部の伸縮、装備同士の干渉を別途実装する。異なる全長の腕脚・任意の外部GLBを自動適合させる規格ではない。

## 操作・生成

`just bastion`で標準GLBと規格JSONを再生成する。ViewerでBASTIONを選ぶとアセンブリ欄が現れ、選択直後に交換する。「構成をGLBで保存」で現在の実体と選択情報を保存し、そのGLBを同じViewerで開くと交換を再開できる。一般のGLBビューアでは保存時の静止機体として表示される。

「再読み込み」は読み込み元の構成に戻る。変更の自動保存はしない。「標準構成に戻す」は11モジュールを標準選択に戻す。RAVENなど他モデルでは編集欄を表示しない。

実装は規格`bastion-definition.mjs`、材質と形状語彙`bastion-kit.mjs`、各部品`bastion-parts.mjs`、組立・交換`bastion.mjs`、DOM操作`viewer/assembly.mjs`に分離した。

## 今回の検証とリテイク予防

1. 交換APIが存在しない状態でテストを失敗させ、互換性・接続保持・厚み・接地・GLBを実装した。
2. 足底の高さだけを合わせても、傾けた爪先の端が床へ入った。足全体の実ジオメトリの最低点を検査して修正した。
3. 初稿は同じ角箱が並び、玩具的な印象だった。胸・肩・頭・脛を独立した断面の傾斜装甲へ置き換えた。ボルトを増やす前に大きな輪郭を変える。
4. ボルトを機体全体の座標へ別置きすると、傾斜装甲から浮く。前腕と脛のボルト・識別番号は、対象パネルの子としてパネル面のローカル座標へ配置した。
5. 正面だけで完了にせず、側面・反対側・背面・斜め後ろを出力して確認。画像検査を形状の数値テストの代わりにせず、両方使う。

Nodeテストは全選択肢の交換、未知ID拒否、他部品不変、有限座標・単位法線、接地、胸の前後幅、リソース所有、GLB validatorを検査。Playwrightは多方向表示・左右独立の交換・GLB保存／再読込・標準構成復帰・RAVENへの切替・モバイルを検査する。Pagesのサブディレクトリビルドでも読込と交換を検査する。

現段階は静止モデルとパーツ交換の初稿。アニメーション、重量による挙動、反動、射撃演出、衝突、耐久値、全組合せの干渉保証は含まない。テスト合格は公式機体への類似度や美術的な完成度の保証ではない。
