# IRON YARD — ロボットTPSの移動・戦闘基盤

[公開版でプレイ](https://mizchi.github.io/modeling-playground/game.html) / [ローカルで操作](http://127.0.0.1:5188/game.html) / [TPS画面](../output/game-tps.png) / [出撃メニュー](../output/game-deployment.png)

STRIXを操作機、BASTIONを3機の静止標的として使用する、React Three Fiber製の別ページ。既存のモデルビューア・パーツ交換・モーション編集は変更せず、生成済みGLBを共用する。移動・ジャンプ・空中ブースト・射撃・マルチロックミサイル・命中／撃破まで実装。敵AI・反撃・プレイヤーの被弾はまだない。

## 操作

| 操作 | 内容 |
| --- | --- |
| 出撃する／操作を再開 | マウス固定を要求して操作開始 |
| WASD | カメラ基準の前後左右移動 |
| マウス | TPSの水平・垂直視点。垂直角に上限・下限あり |
| Shift＋移動 | ブースト姿勢による低空の高速移動 |
| Space短押し | 接地中にジャンプ |
| Space長押し | 約0.22秒で上昇ブーストへ移行。WASDも高速移動になり、離すと落下 |
| 左クリック長押し | ライフル連射。銃口から画面中央の注視点へ発射 |
| E長押し→離す | 最大3機をロックし、各標的へ2発ずつミサイルを斉射 |
| Esc | 停止してマウス固定を解除 |
| 出発地点へ戻す | 位置・速度・視点・空中状態・標的HP・弾・ロック・戦績を初期化 |

Pointer Lockが拒否される埋込みプレビューでは右ドラッグ視点へフォールバックする。ウィンドウのフォーカス喪失・タブの非表示・固定解除でも入力を消して停止する。主対象はキーボードとマウスを備えたPC。狭い画面でメニューは収まるが、タッチ用スティック・ゲームパッドは未実装。

## ステージとモデル

約96 × 114 mの平坦な工業区画。左右の倉庫、コンテナ、中央遮蔽物、外周壁、冷却塔と遠景を配置。出発パッド、黄色の車線、BASTIONの配置リングで向きを確認する。建物の描画と衝突は同じ寸法定義から作り、BASTIONにも箱状の衝突領域を置く。出発地点は変えず、引いたカメラが外周壁の裏に回らないよう後方の区画を10 m拡張した。

操作機の衝突は半径3 m・高さ3.6 mの円柱近似。上から見た四脚の広がりを含む保守的な近似で、足ごとの衝突ではない。小さなサブステップと円／箱の押し戻しで壁沿いの移動と外周制限を行う。高さも検査し、箱型の屋上への着地、端からの落下、天井との衝突に対応。坂道、細かい地形IK、剛体力学は対象外。

歩行速度は3.2 m/s、ブーストは14.4 m/s（初版のそれぞれ2倍）。加減速は指数補間。STRIXの既存の対角歩行を実移動距離から進め、静止時とブースト姿勢へ補間する。ゲーム中は元の`Boost`単発クリップのルート前進を加算せず、移動ロジックを位置の唯一の所有者にする。

Spaceの押し始めに上向き8 m/sを与え、重力18 m/s²でジャンプ。長押し後は上昇速度7.5 m/sへ補間し、離すと重力で落下する。空中で押し直しても二段ジャンプにはならない。燃料消費はなく高度上限40 mで上昇を止める。四脚を畳む空中ポーズと噴射量は分離し、短いジャンプや落下ではブースターを点け続けない。カメラ支点と実際の武器の発射位置も高度へ追従する。

脚部シャーシは移動の「向き」ではなく「軸」に最小回転で合わせ、180度違う方向を同じ軸として扱う。前後・左右の切り替えで180度旋回せず、斜め移動も現在角から90度以内の候補へ補間する。停止時は脚部の向きを保つ。後退は歩行位相の増分を逆向きに積算し、入力を反転した瞬間のポーズ飛びを防ぐ。

腰から上の胴体・頭・砲身・ライフルは画面中央の注視点へ向け続ける。横移動・後退・ブーストでも胴体は移動方向へ引きずられない。注視点は実際のカメラ位置から中央の視線を伸ばし、標的／建物の衝突箱か床に当たった最も近い点（何もなければ100 m先）。腰の機械的な可動角制限はまだ設けていない。BASTIONは静止モデルを複製しており、戦闘行動や歩行リグを追加したものではない。

カメラの基準距離を12→17 mに変更。支点・前方注視点の高さと肩越しオフセットも合わせて調整し、自機を画面下側に寄せて中央を空ける。壁付近では非貫通を優先して距離を縮めるため、常に17 mを保つわけではない。

## 射撃・ミサイル

- ライフルは右手の実銃口から130 m/sの弾を発射。発射間隔0.12秒、1発12ダメージ。弾数は無制限。
- ミサイルはカメラ前方約26度・95 m以内の、建物で遮られていない標的を最大3機選択。Eを約0.65秒保持してロック完了し、離すと1機あたり2発を0.12秒ずつずらして肩部から発射する。再装填3秒、1発55ダメージ。
- 最初の約0.65秒は上向きの初速と重力による放物線状の打ち上げ。その後は標的へ速度ベクトルを曲げて追尾する。移動標的への追尾も計算は対応するが、現在のBASTION自体は動かない。
- 弾のフレーム間の線分で障害物・標的・床との衝突を検査し、高速弾のすり抜けを防ぐ。命中判定は機体全体の箱で、部位別装甲や爆風の範囲ダメージはない。
- BASTIONは各180 AP。HPが0になると爆発表示の後ではなく命中時点で描画・衝突・ロック候補から除去する。残存弾は寿命で消え、撃破済み標的へ向けた未発射弾はキャンセルする。
- ロック枠、HP、再装填、命中数、撃破数、曳光弾・煙跡・爆発を表示。Esc・blurなどの停止ではロックと未発射の斉射予約を破棄し、再開だけで勝手に発射しない。

## 責務と次の接続先

| ファイル | 責務 |
| --- | --- |
| `game/types.ts` | 入力・機体状態・ステージ・配置機の型 |
| `game/stage.ts` | ステージ配置と衝突寸法、配置機ID |
| `game/simulation.ts` | DOM・Reactに依存しない移動、衝突、TPSカメラと中央注視点の計算 |
| `game/animation.ts` | `PilotAnimator`。脚の移動姿勢と腰・頭・武器の注視方向を分離 |
| `game/combat.ts` | 戦闘の型、HP、ロック、発射予約、弾道・追尾、衝突・撃破。純粋更新関数 |
| `game/CombatScene.tsx` | 戦闘フレームの接続、弾／煙／爆発のインスタンス描画、低頻度の戦闘HUD |
| `game/controls.ts` | キー・マウス・Pointer Lock・解除時の入力クリア |
| `game/Stage.tsx` | ステージ描画、光・影・環境 |
| `game/Robot.tsx` | 骨格複製、アニメーター接続、複製リソースの解放。元のGLBキャッシュは変更しない |
| `game/main.tsx` | R3F Canvas、フレーム進行、メニュー、低頻度のHUD更新 |

ゲームはReact 19／R3F 9で構成。[公式の対応関係](https://r3f.docs.pmnd.rs/getting-started/installation)を確認し、フレーム内ではrefとThree.jsオブジェクトを更新する。HUDだけを約10 HzでReactへ通知し、フレームごとのReact再レンダーを避ける。[R3Fのフレーム更新に関する注意](https://r3f.docs.pmnd.rs/advanced/pitfalls)。

フレーム順序は移動・カメラ→骨格ポーズ・武器の発射位置→戦闘更新・描画。銃口のローカル座標を、そのフレームのボーン変換でワールド座標へ移す。[Three.jsの座標変換API](https://threejs.org/docs/pages/Object3D.html#localToWorld)。元のGLBやモデルビューアの武器定義は変更していない。次の拡張は敵AI・反撃、プレイヤーHP、武装交換、効果音、ミサイル用の専用ランチャー外観。

## 検証

`just game-check`でTypeScript strict、移動・骨格・戦闘の単体テスト、ゲームのPlaywrightテストを実行する。`just test`にもゲームの型検査と単体テストが含まれる。`just test-pages`は新しい`game.html`も本番サブディレクトリで検証する。

- カメラ基準の移動、斜め入力の速度正規化、状態を破壊しない更新。
- 30 Hz／120 Hzでの移動距離、加減速、ブースト。
- 壁の通り抜け防止、壁沿いの移動、外周、カメラの壁手前への引込み。
- 歩行／ブーストの2倍速、出発地点の実カメラ距離・画面内投影・壁との位置関係。
- 横移動・後退・ブースト時の胴体／頭／武器の正面軸と注視点の一致。
- 逆方向でも同じ脚部軸へ収束すること、反転の全フレームで旋回しないこと、停止時の軸保持、逆歩行の位相連続性と初期化。
- 再読込GLBの照準変更が脚のポーズ・共有骨格・移動状態を変更しないこと。
- 実GLBの読込、WASD、視点変更、Shift、Esc、再開、フォーカス喪失、初期化。
- Pointer Lock拒否時の右ドラッグ操作、狭い画面のメニュー。
- ゲームのE2EはPointer Lock拒否を明示して右ドラッグ方式に固定する。許可経路はDOMイベントの単体テストで、相対マウス移動・移動／武器入力・固定解除／再開を検証する。CIにおけるネイティブのマウス固定と3D画面の組合せを保証するものではない。
- 銃口からの射撃、HP減少、薄い壁での遮断、30／120 Hzで同じ発射数、二重撃破の防止。
- ロックの待機時間・範囲・背後／遮蔽物の除外・3機上限、複数標的への斉射・移動標的への追尾・停止時のキャンセル・弾の寿命。
- Space短押し／長押し／離す操作、二段ジャンプ防止、屋上着地／天井／高度上限、空中の照準と射撃、再開時の入力クリア。

60 Hzの性能や、全ての遮蔽物間での機体・カメラの非貫通を保証するものではない。静的メッシュの統合、描画呼出し削減、LOD、地形検出は今後の工程。

## 次の工程で繰り返さないこと

- ルートモーションを持つモデルにゲーム側の前進を加えると二重移動になる。位置の所有者はsimulationに固定し、モデルからは関節姿勢と浮上量だけを使う。
- カメラを横へずらしても`lookAt`が常に機体中心なら、機体は画面中央に残る。壁検出用の追従支点と、照準を空けるための前方注視点を分離する。
- 腰をローカル角だけで合わせると、シャーシの旋回やブースト時の親ボーンの傾斜が照準に加算される。狙うワールド回転を親の逆回転でローカルへ変換する。既存ポーズで逆方向に傾けている頭・砲身・グリップも個別に合わせる。
- 前後対称の四脚を移動ベクトルの向きへ回すと、後退入力だけで180度旋回する。脚部は180度周期の軸として最短角を選び、±90度の同距離候補も一貫した側へ解決する。逆歩行では累積位相全体に符号を掛けず、増分だけを符号付きで積算する。停止時にカメラの向きへ戻すと再び余計な旋回が起こるため軸を保持する。
- 構図用の近い`lookAt`点をそのまま武器の狙いにしない。壁で補正した実カメラから視線を伸ばして注視点を得る。
- カメラ位置自体の非貫通と、自機が遮られず見えることは別。外周壁を越えたカメラからは壁上部が自機を隠す。距離・投影の数値テストだけで終えず、実画面で足元まで確認する。
- Pointer Lockは実行環境によって拒否される。拒否時は停止画面から進めない状態にせず、右ドラッグで操作できるようにする。固定解除・blur・visibilitychangeではキーを消し、復帰時の暴走を防ぐ。
- CIとローカルでPointer Lockの可否を成り行きにすると、同じ絶対座標のマウス操作が別の視点操作になる。固定中は「カーソルを中央へ戻す」操作自体も視点を動かす。ゲームシナリオの入力方式を固定し、許可／拒否の入力コントラクトは分離して検証する。標的待機もテスト全体の120秒まで待たず、短い可視性アサーションで異常を報告する。
- `useLoader`のモデルはキャッシュ共有されるため、機体ごとに骨格を複製する。位置や姿勢の操作は複製側だけに行い、共有ジオメトリ・材質を機体の破棄時にdisposeしない。
- 発射位置を前フレームのボーンから読むと旋回・上昇中に弾がずれる。移動→骨格→発射位置→戦闘の更新順を固定し、銃口から標的までの線分で遮蔽物を判定する。カメラから見える標的でも銃口前に壁があれば弾を止める。
- 「キーを離したら発射」はEscやフォーカス喪失でも成立しがち。停止時は単なるkeyupではなく明示的キャンセルとして、ロックと未発射予約を破棄する。
- ジャンプの押下エッジと上昇ブーストの保持時間を分離する。空中の脚を畳む量と噴射量も分け、垂直速度だけで脚部の水平軸が回転しないようにする。

共有メモリへの保存は既知の権限不足のため行わず、このリポジトリ内のノートを引継ぎ先とする。
