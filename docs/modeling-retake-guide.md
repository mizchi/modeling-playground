# 次のキャラクターモデリングで繰り返さないこと

Ashley の制作で起きたリテイクを、次のモデルの制作手順へ変換したガイド。新しい人型モデルの着手前と、形状のリテイク前に読む。

具体的な変更履歴・実装位置は [Ashley 制作ノート](ashley-study.md)、共通処理とモデル固有コードの分離は [アセット設計](asset-architecture.md) を参照する。この文書には再発防止の判断基準を置き、各試行の数値は複製しない。

## 最重要：正面の絵から厚みを後付けしない

今回のエージェントの偏りは、正面から見た顔・輪郭・衣服の帳尻を先に合わせ、側面の厚みと背面の構造を後回しにしたこと。正面では成立しても、横から見ると頭・首・胴体が薄く、弱く見えるモデルになった。これは細部の不足ではなく、初期の形の決め方の問題だった。

**正面・側面・背面・斜めを一組として作る。正面が似ただけで、細部の制作へ進まない。**

- 初稿から頭蓋、胸郭、骨盤を前後幅のある立体として置く。正面の輪郭を浅く押し出した形を完成形の土台にしない。
- 顔の幅だけでなく、額〜鼻〜顎の側面、耳より後ろの頭蓋、首の位置を同時に決める。
- 胸板だけ厚くせず、背中側の量感と、腰への絞り・骨盤への戻りを作る。
- 側面資料が不足しても、奥行きをほぼゼロと仮定しない。補完した厚みを明示し、早い段階で側面を見せる。
- 側面・斜め後ろの確認を、ユーザーから指摘されて初めて行う工程にしない。

### Ashley で有効だったこと：背筋が立体感を作った

ユーザーの評価では、背中の背筋をモデリングしたことで、モデルに立体的な深みが出た。これを今回の成功パターンとして残す。

強さを出すために肩幅や上腕を太くするだけでは足りない。首の後ろから上背部へ続く厚み、肩甲骨周辺の量感、胸郭の後方への張り、腰のくびれが、側面と斜め後ろのシルエットを成立させる。背中は「見えない裏面」ではなく、身体の厚みを作る主要な面として扱う。

今回のコードでは主に、胴体の断面中心と前後幅、首との接続でその量感を表現している。個々の筋肉を細かく彫った完成解剖モデルという意味ではない。次回もまず大きな量感を作り、筋肉の筋や細かな陰影は後から加える。

注意：背筋を作ることと、全身を一律に太くすることは別。Ashley では胸・背中の厚みを増す一方、上腕は少し細くして対比を整えた。S 字も自然な立位の範囲に留める。

## 次回の制作順序と通過条件

| 段階 | 作るもの・確認するもの | 次へ進む条件 |
| --- | --- | --- |
| 1. 資料と基準 | 正面・左右側面・背面・斜めの資料、座標軸、立位、体格、特徴の優先順位 | 資料で分かる部分と補完する部分を区別した。構えやカメラの遠近を素体に焼き込んでいない |
| 2. 大きな立体 | 頭蓋・首・胸郭・背筋の量感・腰・骨盤・四肢。まず単色で確認 | 横から頭と胸背部の厚みが読める。首から背中がつながり、斜め後ろでも身体が薄くない |
| 3. 顔の構造 | 額・鼻筋・頬・顎角、眼窩と眼球表面、目と口のループ | 鼻と顎が側面で成立する。目の面の向きが正しく、目・まぶた・頬が一体としてつながる |
| 4. 髪と衣服 | 頭皮面、役割別の髪束、身体に沿う布、裾、ベルト、接続する紐 | 髪が頭蓋を覆い、服の面が身体を突き抜けない。紐を片端から他端まで追える |
| 5. テクスチャと出力 | UV、目元・髪・素材の描画、GLB 再読込、共通 Viewer | 形状の不備を影の描き込みで隠していない。複数方向の表示と出力検証を確認した |

段階 2 の厚みが成立していなければ、瞳や髪の模様を描き込む前に戻る。テクスチャを外した単色表示は次回の推奨確認方法であり、現在の共通 Viewer に専用切替があるという意味ではない。

## リテイクの失敗パターンと予防策

### 1. 正面の幅で体格を表そうとする

- 最初の失敗：顔・肩・腕の横幅を調整しても、側面の頭部・胸郭・背中が薄いままだった。
- 有効だった修正：胸背部の前後幅、背筋の量感、首から上背部への接続、胸郭・腰・骨盤の S 字を整えた。
- 次回：横幅と奥行きを同じ段階で決める。筋肉量は正面の太さだけで評価せず、側面の厚みと背面の面の流れで評価する。
- 確認：左右側面・斜め後ろの全身と上半身。肩から腕への接続、胸と背中の両側を見る。

### 2. 「シャープに」を顎の細さだけで実装する

- 最初の失敗：顎を絞りすぎ、尖った顎先と、耳へ急上昇する下顎線になった。一方、水平な底面もヘルメット状に見えた。
- 有効だった修正：顎先の幅と下面、低い顎角、耳へ緩やかに上がるラインを分けて調整した。
- 次回：顎先・顎角・耳下を別の基準点にする。シャープさは細さ一つでなく、面の向きと輪郭の傾きで作る。
- 確認：正面の顎幅と側面の下顎線を同時に確認する。首の接続も含める。

### 3. 局所的な押し出しで精悍さを作ろうとする

- 最初の失敗：頬骨や目元だけを前に出し、周囲との段差・板状の張り出しが発生した。
- 有効だった修正：額・眉・頬・顎の大きな面を連続させ、頬の浅いくぼみと顎角の支えを調整した。
- 次回：一点を動かす前に、影響する隣接面を決める。出っ張りの頂点だけでなく、その上下と側面への接続を設計する。
- 確認：斜めからの陰影とシルエット。不要な棚状の段差がないこと。

### 4. 目の向きの問題を、眼窩の深さで解こうとする

- 最初の失敗：目の描画を頬の丸みに沿う面へ置いたため、斜めから目が外向きに見えた。眼窩を深くするだけでは向きは直らなかった。
- 有効だった修正：顔の大きな曲面とは別に、正面を向く凸面を目の内側に定義し、目頭側・目尻側の奥行きを揃えた。
- 次回：最初に「位置」「向き」「丸み」「まぶたの開口」「UV」「描画」を切り分ける。正面を見据える目を、頭の側面へ回り込む面にそのまま描かない。
- 確認：目頭側・目尻側の対称位置、凸面の中心、左右の視線。正面と左右の斜めで見る。

現在の Ashley の目は顔と一体の凸面パッチ。独立した球体眼球や視線制御ではない。次に眼球回転や瞬きを扱う場合は、この構成をそのまま万能な眼球実装として流用しない。

### 5. 「もっと深く」を一つの数値の増加として反復する

- 最初の失敗：眼窩の補正係数を増やし続け、目だけが穴の奥に沈んだ。眉・鼻との遮蔽や、下まぶた〜頬の段差が大きくなった。
- 有効だった修正：目の向きと中央の丸みを整えたうえで、目を少し前へ戻し、眼窩と頬の境界も緩めた。
- 次回：ユーザーの「深い・強い・鋭い」という意図を、単一パラメータに固定しない。深さ、向き、周囲の形、照明・描画のどこが印象を作っているか、都度確認する。
- 確認：係数ではなく、実際の三角面上の位置と見え方を比較する。複数回の微調整で改善が伝わらない場合は、同じ係数を増やす前に仮説を見直す。

### 6. トポロジーを変えれば造形も自然になると思う

- 最初の失敗：高さ方向の断面だけで顔を作り、目・口や側面への流れを局所補正で合わせようとした。
- 有効だった修正：目・口にループ、頬の側面に補助列を追加し、形を決めるパラメータと面の接続を分離した。
- 次回：必要な面の流れを先に用意する。ただし、ループがあること自体は「似ている」「自然」の証明ではない。頂点位置と面構造は別々に確認する。
- 確認：閉じた接続、面の向き、UV の連続性と、複数方向での形状の両方。

### 7. 髪を正面の記号だけで作る

- 最初の失敗：跳ね毛が上向きの角になり、前髪の上げる部分・下ろす部分・横へ流す部分が曖昧になった。
- 有効だった修正：各部分の役割を分け、側面資料に合わせて長い房を後方へ流し、根元を頭皮へ接続した。
- 次回：髪束ごとに根元・方向・終端を定義する。正面の折れ線だけから奥行きを決めない。
- 確認：生え際の明瞭さ、根元の浮き、横・後ろからの房の向き。

### 8. 薄さを直すために後頭部と髪を一律に膨らませる

- 最初の失敗：厚み不足への対処で後方成分を増やした後、頭蓋と髪の厚みが重なり、襟足も巻いたように見えた。後から端点だけ縮めると頭皮を貫通した。
- 有効だった修正：承認済みの顔を固定し、後頭部を詰め、髪を頭皮へ合わせた。補助列を追加し、襟足の束を短く整理した。
- 次回：頭蓋の体積・髪の厚み・髪束の長さを独立して扱う。太くするだけでなく、被覆と余分な厚みの両側に限度を設ける。
- 確認：後頭部の最大張り出し、襟足から首への流れ、髪の頂点間で頭皮が突き抜けないこと。

### 9. 服の頂点が外にあれば、面も外だと思う

- 最初の失敗：胸当ての頂点だけ身体の外へ置いても、三角形の途中で胸や腰が突き抜けた。単純な細分化だけでは解決しなかった。
- 有効だった修正：衣服の輪郭を身体の実際の三角形で切り抜き、面に沿わせた。ベルトは肌・布・紐の全レイヤーを包む輪郭から生成した。
- 次回：衣服は身体との関係から作る。ベルトの断面数を変えたら、異なる断面の間で交差しないか確認する。
- 確認：頂点だけでなく面の内部、複数の高さと周方向で被覆を検証する。

### 10. ズボン・肌・股上を独立した閉じた部品として重ねる

- 最初の失敗：肌が裾から飛び出し、底面の蓋が脚を横切った。裾を直しても、股上には肌色の箱が残った。
- 有効だった修正：肌を裾で終端し、同じ断面から布へ接続した。股上を左右のズボンと同じ服として整え、不要な蓋をなくした。
- 次回：衣服の開口部と連続する領域を先に決める。部品単体が閉じていることより、組み合わせたときの構造を優先する。
- 確認：裾の全周、股下、前後の UV、布の終端と肌の始端。

### 11. 紐を接続構造でなく、見える線として描く

- 最初の失敗：前掛け・肩越し・背面の紐を別々に置き、端がつながらなかった。表面から大きく離して貫通を避けたため、横から浮いて見えた。
- 有効だった修正：前掛け上端から首の左右、背面中央、背面の布まで経路をつなぎ、身体と服へ投影した。
- 次回：「何を何につなぐ紐か」を先に定義する。接続点を共通の基準にし、装飾線として後付けしない。
- 確認：見た目だけでなく、各端の接続先までの距離と、途中の浮き・食い込み。

### 12. 陰影の継ぎ目を形の段差だと思って盛り直す

- 最初の失敗：首と胴体の重複した蓋、UV 境界で分かれた法線が、不自然な縁や陰影を作った。
- 有効だった修正：接続断面を合わせて内部の蓋を除き、UV の分離を保ったまま法線を共有した。
- 次回：盛る・削る前に、輪郭の問題か、面の接続か、法線か、描画かを分ける。影を描き足して形状の不備を隠さない。
- 確認：ワイヤーフレームと単色の陰影を使い分ける。法線を共有すべき境界と、硬いエッジを区別する。

## リテイクの進め方

1. 指摘された見え方を短く記録し、画像の角度を再現する。ユーザーが言った部位と、原因の部位が同じとは限らない。
2. 原因の仮説と、今回変える範囲・固定する範囲を決める。顔が承認された後は、後頭部や紐の変更で顔まで動かさない。
3. 比較用の画像を変更前に残す。正面だけでなく、指摘された角度と反対側も保存する。
4. 数値化できる破綻は Red → Green で検証する。形の印象は数値テストだけで判定しない。
5. 一度に変える原因を絞り、再生成した GLB を読み込む。同じカメラ・倍率・照明で変更前後を比べる。
6. 指摘角度が改善しても、正面・左右側面・背面・左右斜め・斜め後ろを確認する。手直しした面の裏側も見る。
7. 形のまとまりを確認してからリファクタする。採用した修正と、採用しなかった仮説を短く残す。

現在の確認画像は再生成で上書きされるものが中心。次回は比較用の画像を別名で保存し、「前より何が変わったか」を失わない。現在の E2E は正面・片側の側面／斜め・背面等を確認するが、左右全方向の比較を自動化済みとはみなさない。

### テストの役割を間違えない

- 形状・被覆・接続・法線・UV・出力の破綻はテストで防ぐ。「似ている」「自然」は画像とユーザーの評価で判断する。
- 深さや幅の下限だけでなく、過剰な変形を止める上限と、周囲との差を検証する。
- パラメータを変えて旧テストに失敗したら、実装の不備か、ユーザーの変更意図で旧条件が無効になったのかを区別する。通すためだけに許容範囲を広げない。
- 再トポロジーでは旧頂点番号に依存せず、UV やランドマークから実際の面を評価する。係数の最大値と、粗い三角面の変位は一致しない。
- 承認済みの箇所は必要に応じて位置・UV のハッシュなどで固定する。固定は造形の普遍的な正しさでなく、承認状態を保護する契約。
- Ashley の寸法・比率・三角形数・テクセル数を、別のキャラクターの普遍的な合格値にしない。

既存の検証は [形状・衣服・目・髪・紐のテスト](../tests/ashley.test.mjs)、[トポロジーのテスト](../tests/ashley-topology.test.mjs)、[GLB 表示の E2E](../tests/e2e/ashley.spec.mjs) を参照する。見た目の自然さをコードの構文だけで判定する lint は追加しない。

## 制作前・提出前の短いチェックリスト

- [ ] 正面の帳尻から始めず、最初に側面の頭蓋・首・胸郭・背中の厚みを作ったか。
- [ ] 背筋・肩甲骨周辺・腰の量感があり、斜め後ろからも立体として読めるか。
- [ ] 目の位置・向き・丸み・開口・描画を、眼窩の深さ一つで解こうとしていないか。
- [ ] 顎先・顎角・首と、頬・目の下のつながりを見たか。
- [ ] 頭蓋と髪を一緒に膨らませすぎていないか。髪の根元と襟足を見たか。
- [ ] 衣服の面の内部、裾、股上、ベルトの全レイヤーを確認したか。
- [ ] 紐の両端と経路が実際につながっているか。
- [ ] 指摘角度だけでなく、反対側と背面にも新しい破綻がないか。
- [ ] テスト合格を、自然さや完成度の保証として報告していないか。
- [ ] 承認済みの部分を守り、変更前後の比較と採用理由を残したか。
